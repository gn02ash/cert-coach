# Security

Cert Coach is a personal study app: one person's plans, PDFs, practice history and career profile. This page
says what it protects, how, and what you need to do yourself if you run it anywhere other than your own machine.

## Reporting a problem

Please don't open a public issue for a security problem. Report it privately: through **Security → Report a
vulnerability** on this repository where that option is shown, or otherwise by contacting the maintainer through
their GitHub profile. Include steps to reproduce.

## What is protected, and how

### Signing in

- **Browser:** the API runs the Microsoft and Google sign-in flows itself (backend for frontend). The browser only
  holds an `HttpOnly`, `SameSite=Lax` session cookie, never an access token, so script on the page can't read
  anything that signs you in. Accounts are matched by the provider's subject ID, never by email.
- **Cross-site requests:** every state-changing request, logout included, needs an `X-CSRF` header, which another
  site can't add to a request without the API's permission (it gives none).
- **Open redirects:** the post-sign-in return address must be a path on this site.
- **AI assistants (MCP):** personal access tokens, created on the Connect page.
  - 256 random bits, shown once. Only a SHA-256 hash is stored, so a copy of the database signs no one in.
  - They expire (30 days to a year), can be revoked at once, and are limited to 10 per learner.
  - A token is accepted **only** on `/mcp`, and the session cookie **only** on the web API. A leaked token
    can do what the MCP tools allow, and no more: it can't manage tokens or reach the rest of the API.
  - The MCP tools read, quiz and mark sessions done. None edits or deletes anything.

### Your data

- **One learner can't see another's.** Every service checks ownership explicitly, and the database context adds
  an owner filter to every query as a second line of defence. Integration tests check isolation for each area.
- **Your CV is never stored.** It is read in memory for one request and discarded; only the profile you save is
  kept, and you can delete it.
- **Uploaded PDFs** are stored under IDs generated by the server, never under their file names, and the file store
  refuses any path outside its folder.
- **Secrets** live in environment variables (`.env`, which git ignores). Nothing secret is in the repository or
  its history, and the YouTube key is sent in a request header so request logs never contain it.

### Talking to other services

- **Importing an outline from a URL** fetches pages you name, so it is the one place an attacker could aim the
  server at something internal. Every connection is checked after DNS resolution and on every redirect, and
  private, loopback, link-local (including cloud metadata) and other special addresses are refused. Responses are
  limited to 5 MB and 20 seconds.
- **Everything else the server fetches** (Microsoft Learn's catalogue, YouTube search, the AI providers) goes to
  fixed public hosts.
- **Prompt injection:** documents, web pages and CVs reach a model inside tags it is told to treat as data, and
  the tags can't be closed from inside. Model output is checked before use: citations must point at real passages,
  generated questions must pass the domain's rules, recommendations can only name catalogue entries, and the
  outline agent's one tool can only read pages on one site.

### Abuse and cost

- **Rate limits** per learner (or per IP address before sign-in): 600 API requests a minute, 30 a minute for
  anything that calls a model or the internet, 120 MCP calls, and 20 sign-in attempts per IP. They are set
  under `RateLimiting` (`ApiPerMinute`, `CostlyPerMinute`, `McpPerMinute`, `SignInPerMinute`).
- **Request size:** 2 MB, except PDF uploads (50 MB) and CV uploads (5 MB).

### In the browser

- A strict Content Security Policy on the app's pages: only its own scripts, styles and connections, no plugins,
  and no framing. React escapes everything it renders, and the app never inserts raw HTML.
- `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, a `strict-origin-when-cross-origin` referrer
  policy, a permissions policy that turns off camera, microphone and location, and no server version.

### The supply chain

- Package versions are pinned centrally (`Directory.Packages.props`, `package-lock.json`). `dotnet list package
  --vulnerable` and `npm audit` reported nothing on 2026-11-12.
- The API container runs as a non-root user.

## Running it beyond your own machine

The defaults are for one person on their own computer. Before anyone else can reach it:

1. **Turn off the dev login:** `AUTH_DEV_LOGIN=false`. With it on, anyone who can reach the app signs in as you,
   without a password. The API logs a warning at startup while it is on.
2. **Configure Microsoft or Google sign-in**, with your public address in the provider's redirect URIs.
3. **Serve it over HTTPS** with a reverse proxy or load balancer in front of the `web` container. The session
   cookie is marked `Secure` once requests arrive over HTTPS. Add `Strict-Transport-Security` at that proxy.
4. **Set a strong `POSTGRES_PASSWORD`.** The database port is published on `127.0.0.1` only; keep it that way.
5. **Back up the `keys` volume** with the database. It holds the keys that encrypt session cookies.
6. **Keep the AI and YouTube keys to the minimum scope** their providers allow, with spending limits set there.

## Known limits

- It is built for one learner per deployment. Several can use it, and their data is kept apart, but there are no
  roles, administrators or sharing.
- Rate limits are counted in memory, per API instance.
- Uploaded PDFs are parsed by PdfPig in the API process. A malicious PDF is a theoretical risk to that process,
  which runs as a non-root user with access only to its own volumes.
